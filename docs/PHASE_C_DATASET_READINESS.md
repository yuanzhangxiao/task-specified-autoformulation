# Phase C dataset readiness

This milestone creates **`phase-c-development-1`**, an isolated development
release for CSTR, alien-device and stormwater detention basins. It preserves
historical Phase-B datasets, the `_rates_v1` release, old prompts and fitter
profiles. Fitting improvements are parked in
[the fitting findings note](PHASE_C_FITTING_FINDINGS_2026-09-28.md).

T3/T4 are outside this Phase C roster. The twelve cells above are a **development
release for stage isolation**, not a claim that the full planned 28-cell roster
or final evaluation suite is ready. No fitting, pruning, LLM calls or candidate
test evaluation is performed. Test payloads are not generated by this command;
final held-out protocols must be frozen and released separately before final
comparisons. Existing historical test sets remain untouched.

## Alien-device correction

The old hard design contained three indistinguishable public initial situations:
zero command throughout, initial output zero, but three different private hidden
preparations. No deterministic predictor initialized only from the public
information could reproduce all three outputs.

The new design resets every hidden coordinate to the same preparation before
each run. The reset's numerical internal coordinates and dimension are not
revealed in the prompt. The two former training hidden perturbations instead
vary the **measured initial output** to +0.5 and -0.5. The protocol definitions
also map the reserved hidden-initial test perturbations to measured output
perturbations; those test trajectories are not generated here. The external
command schedules and internal differential equations are unchanged.

The public prompt explicitly states the common preparation, shared hidden
initialization and use of the measured initial output. Latent states can still
store input history and produce delayed, persistent and nonlinear effects.
Resetting preparation does not eliminate the need for internal memory.

The public-data regression reproduces the historical contradiction and verifies
that the new design removes it. A second check verifies directly, on the private
reference, that hidden initial coordinates are identical across development
runs. This latter check is evaluator evidence, not additional proposer input.

## CSTR preparation consistency

CSTR's earlier assisted affine initialization witness covered its training design
and equilibrium validation initials. It did not cover independently changed
hidden preparations in the historical held-out design. The new release fixes
initial concentration and jacket temperature to their common preparation while
retaining the measured reactor-temperature shifts. The same rule applies to
training, validation and reserved test protocol definitions.

Easy still supplies the original auxiliary channels. Hard still observes only
the target temperature. An evaluator-only exact-equation witness initializes
hidden quantities with shared constants and initializes temperature from its
public observation. It does not use a trajectory identifier or private
per-trajectory initial labels. Those shared constants are unknown to discovery
and can be estimated on training. This qualification performs no optimization.

## Basin benchmark

The existing detention development design is included without changing its
physics or public prompt. Two coupled basins have unequal surveyed areas,
measured inflows, shared volumetric transfer and threshold-dependent discharge.
A public initial upstream gauge reading supplies the otherwise hidden upstream
initial storage; only downstream depth is a prediction target. Both initial
readings remain calibrated in the noisy condition.

The independent control removes the physical connection, so upstream memory is
not required for predicting downstream depth. Each case has six training and
three validation events, with noiseless and 1% observation-noise versions. Noise
scale comes from clean training output; validation does not set it.

The generating discharge law is the existing piecewise-linear rating table.
The evaluator transcribes it as an exactly equivalent analytic hinge sum. This
is not a claim that the generating law is exactly head to the 3/2 power, nor that
we changed the fitter to accommodate that power at zero. See
[the basin specification](DETENTION_BENCHMARK.md) for physical assumptions and
rating-table approximation details.

## Qualification gates

For CSTR and alien-device, every development protocol receives:

1. Independent reference solver and output-grid refinement checks with the same
   fixed public piecewise-linear input schedule.
2. A check that the declared reset really keeps hidden initial coordinates fixed.
3. A public-information collision check: identical full input/auxiliary schedules,
   initial target observations and fixed covariates cannot have contradictory
   deterministic target traces. Trajectory IDs are excluded from that check.
4. An exact-equation witness compiled through the restricted grammar and run
   through the production free-rollout interface, using Radau and DOP853. It
   requires each development trajectory's NMSE <= 1e-6 and solver discrepancy
   <= 1e-4 training target standard deviations. The actual arrays, not a
   separately sampled ideal command, drive each rollout.
5. Numerical equality between the two semantic variants for each tier.

Basins retain the generator's independent-solvers, nonnegative-depth,
non-overtopping and integrated water-balance checks. The same compiled production
replay gate runs on clean data; noisy data are not required to match a noiseless
oracle exactly. Calibrated initial readings are checked in both noise conditions.

These are necessary consistency and public-interface attainability checks.
They do not prove unique mechanisms, parameter identifiability, optimization
success, or scientific correctness of a discovered model. Known equations and
constants are evaluator assistance and remain outside the public release.

## Files and consumers

```text
release/
  plan.json                       # sealed source/runtime/design identity
  progress.json                   # incomplete/complete generation progress
  summary.json                    # sealed completion, readiness and file hashes
  public/<cell>/
    specification.json            # sealed public prompt and channel contract
    proposer_prompt.txt
    train.json                    # sealed PublicSplit
    val.json                      # sealed PublicSplit
  diagnostic/                     # evaluator-only; never send to an LLM
    references/                   # private reference arrays, checks and receipts
    <cell>/                       # exact witnesses and replay diagnostics
```

Only a single `public/<cell>` directory is supplied to construction or a baseline.
After operator verification, `phase_c_release.load_public_cell(directory)` returns
its public specification, training `PublicSplit` and validation `PublicSplit`.
It never traverses evaluator directories. The legacy benchmark registry remains
unchanged: use this explicit adapter for Phase C instead of silently substituting
new data into a historical campaign.

Completed family checkpoints are reusable; source, runtime or configuration
changes require a new root. Every retained reference and public artifact is
checksummed. Verification rejects changed content. A failed gate remains a failed
cell in the denominator and prevents the CLI from reporting a usable release.
`progress.json` exists before expensive generation so an interruption remains
visible. Resume does not start fitting or LLM calls.
